## 0. 一句话

> **像用企查查一样查公司：搜一家公司，一页看完基本资料、财务、投资关系图、
> 新闻和来源；看不懂就直接问。**

三类核心动作：

1. **搜公司**（名称 / ticker / 中文名 / 一句话描述）
2. **看公司页**（基本资料 → 财务 → 关系图谱 → 新闻 → 来源）
3. **问一问**（任何页面右下角，带着当前公司上下文）

审核队列、研究运行、检索 explain、调试面板不进公开 UI，只保留 CLI / 内部页面。

## 1. 目标用户

| 用户 | 想干什么 | 熟悉的界面 |
|---|---|---|
| 非技术股民 | "这家公司靠什么赚钱、值不值得看、和谁有关系" | 同花顺、东方财富、雪球、企查查 |
| 普通金融从业者（非量化） | "快速了解一家公司、核对一个数字、看投资关系" | Wind、企查查、天眼查、公司公告 |
| 记者 / 内容创作者 | "找原始来源、复制引用" | 搜索引擎、企查查 |
| 学生 / 求职者 | "这家公司是做什么的、在哪里" | 百度、企查查 |

**共同点：**

- 看得懂财务名词，但不想读原始财报；
- 习惯"搜索 → 公司页 → 切 tab 看不同维度"的结构；
- 会用聊天框提问，但不会配置过滤器、写布尔查询、看关系图 JSON；
- 对"信息是否可信、来源在哪"有要求，但不关心抽取方法。

**不是目标用户：** 量化研究员、需要批量导出/API 的开发者、需要自定义报表的分析师。
这些能力保留在 CLI / MCP。

## 2. 从企查查借什么，不借什么

### 借

1. **顶部搜索 + 简单导航**：首页大搜索框；内页顶栏常驻搜索。
2. **公司页 = 页头 + tab + 右侧栏**：
   - 页头放公司名、代码、地区、行业、成立时间、关键标签；
   - tab 分维度：基本资料 / 财务数据 / 关系图谱 / 新闻动态 / 资料来源；
   - 右侧栏放关键数字、主要股东/投资方、对外投资、相关公司。
3. **关系图谱是一等公民**：独立的「关系图谱」tab，中心节点 + 辐射布局 + 点击下钻 +
   右侧详情面板；下方同时提供列表视图。
4. **表格密度**：财务、股东、对外投资用紧凑表格，不用花哨图表。
5. **搜索结果带关键事实**：名称、代码、地区、行业、指数标签，一行看完。
6. **状态标签**：已核实 / 待核实 / 媒体报道，颜色 + 文字，不只靠颜色。

### 不借

1. **司法风险、商标、专利、招投标**等企查查的登记/风险数据——不是我们的数据范围。
2. **付费墙、会员、导出套餐**。
3. **企查查的蓝色品牌视觉**——借信息架构，不抄品牌；继续用现有的暖灰 + 绿色。
4. **信息轰炸**：不把几十个字段一次铺满，首屏只给结论和关键数字。
5. **内部工具入口**：审核、运行、调试不在产品导航里。

## 3. 设计原则

1. **熟悉的公司页结构，陌生的技术细节。** 页面结构像企查查；BM25、RRF、
   inferred、confidence、coverage tier、matchType、score 一律不出现。
2. **三个动作：搜 → 看 → 问。** 新增功能先问会不会多出第四个动作。
3. **关系图谱必须有，但不能是唯一入口。** 图 + 列表双视图；图为先，列表兜底，
   手机和无数据时也能用。
4. **数字必须能点回来源。** 每个财务数字、关系证据、新闻都带「来源」，点开是
   原文引用 + 网页链接 + 抓取时间；不显示抽取方法和技术字段。
5. **先说结论，再给细节。** 首屏：一句话 + 4 个关键数字 + 主要关系；完整财务表、
   全部来源、全部关系折叠在 tab 或"展开"里。
6. **数据缺失就说"暂无数据"。** 不猜、不补 0、不把 fixture 当真实数据。
7. **中文优先，英文可切换。** 公司名保留原文。
8. **手机可用。** 关系图在手机上提供全屏 + 列表两种形态。
9. **只读。** 普通用户不能改数据；修正走内部审核。
10. **可信感来自来源，不来自术语。** 用"来自 2025 年财报"而不是"confidence 0.95"。

## 4. 页面地图

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | 大搜索框、热门公司、最近查看 |
| `/search?q=` | 搜索结果 | 公司列表 + 市场/指数/行业筛选 |
| `/c/:ref` | 公司页 | 默认「基本资料」tab |
| `/c/:ref/financials` | 财务数据 tab | 核心指标 + 财务表 |
| `/c/:ref/graph` | 关系图谱 tab | 图 + 列表 |
| `/c/:ref/news` | 新闻动态 tab | 时间线 |
| `/c/:ref/sources` | 资料来源 tab | 去重来源列表 |
| 任意页右侧 | AI 助手 | 可收起的右侧助手栏；手机全屏 |

顶部导航（内页）：

```text
OCC 公司百科     [搜索公司名、代码、中文名…]          首页  查公司  关系图谱   中文 ▾  ☾
```

- **首页**：回 `/`。
- **查公司**：聚焦搜索框 / 回 `/search`。
- **关系图谱**：进入 `/graph` 全局图谱（见 §7.6）。
- 不放下拉菜单、不做多级导航。

`ref` 接受中文名、ticker、slug、ULID；解析失败显示候选，不静默跳转。

- 名称：`displayName` + `legalName`（不同才显示）。
- 第二行：ticker、交易所、国家、行业。

- 页头在所有 tab 固定。

└──────────────────────────────────────────────────────────────────────────┘

**图的行为**

- 以当前公司为中心；默认只展开 **1 层**，避免一屏几十个节点。
- 关系按类型分组，围绕中心排布：
  - **投资/股权**（红/橙）：`invests_in`、`owns`、`parent_of`
  - **供应商/客户**（绿）：`supplies`、`buys_from`
  - **竞争对手**（灰虚线）：`competes_with`
  - **合作/合资/授权**（蓝）：`partners_with`、`joint_venture_with`、`licenses_*`
  - **其他**（灰）
- 边方向从主体指向客体：投资方 → 被投公司；供应商 → 采购方。
- 边样式：
  - `verified`：实线 + 深色；
  - `inferred`：虚线 + 琥珀色，标签写"待核实"；
  - `reported`：点线 + 蓝色，标签写"媒体报道"；
  - `rejected`：不显示。
- 节点：公司名 + 一行身份（行业/地区）。点击节点打开右侧详情面板；双击进入该公司页。
- 边点击：右侧显示关系类型、状态、原文证据、来源链接、"进入公司页"。
- 层级 2：可切换，但节点超过 60 个时提示"关系较多，建议只看 1 层"。
- 过滤：类型多选、只看已核实、搜索节点。
- 空状态：中心节点 + 一句"暂未发现公开关系"，并给两个按钮：
  「让助手去查」和「查看新闻」。
- 手机：默认列表视图；点"图谱"进入全屏图，支持双指缩放和拖拽；底部同样有列表。

**与图联动的列表**

- 分组：投资方 / 对外投资 / 母公司或子公司 / 竞争对手 / 供应商或客户 / 合作伙伴。
- 每行：公司名、关系人话标签、状态、证据入口。
- "为什么这么说"展开：原文引用 + 来源 + 日期。
- 关系状态文案：

## 8. AI 助手（问一问）

### 8.1 形态

- **桌面（≥1101px）：右侧 35% 页宽的常驻栏，主内容同步左移让位。** 宽度写死为
  `35vw`，不做拖拽调宽；打开时从右侧滑出，
  关闭时向右滑回；不使用遮罩，页面保持可见、可滚动，和助手共存。
- **左侧内容保持原有列结构**：公司页仍是「主内容 + 右栏」，图谱仍是「图 + 详情」；
  侧栏只压缩可用宽度，不把页面重排成单栏。
- **平板/手机（≤1100px）：从右侧滑出覆盖层**；手机全宽，关闭后回到页面。
- 入口有三个：顶栏「AI 助手」、页头「问一问」、右下角浮动按钮。
- 在公司页打开时，顶部显示"关于 Apple 苹果公司"，并自动注入公司上下文。
- 首页搜索框识别为问题时，直接打开助手栏并发送。

```text

│ AI 助手                            ›   │

├────────────────────────────────────────┤

```

### 8.2 交互

- 打开/关闭只改变右侧栏宽度和主内容让位，**不使用全屏遮罩**；页面始终可见、可滚动。
- 发送后显示"正在查资料…"；默认不显示原始工具名、JSON、token、延迟。
- 工具调用折叠为一行："执行过程 N 步 · M 个来源 · 42s"；点开显示人话工具卡片
  （搜网页 / 打开网页 / 查公司资料 / 查财报 / 发起深研）、计划和来源账本。
- 引用渲染为 `[来源]` chip，点击打开来源浮层；来源账本里的 URL 也新窗口打开。
- 不显示模型名、原始 token 流、trace、权限选项或思考链。
- 错误话术："暂时没查到，换个问法试试"，保留重试。
- 关闭即结束会话，下次新会话。
- 底部固定三个建议问题（与基本资料 tab 的"你可能想问"一致）。

| `get_company` | 查公司资料 |

| F10 抓取 | 查最新财报 |

### 8.4 轨迹与子代理（tool use + 会话回放已实现；子代理卡片预留）

> 工具轨迹（P3.4 UX v3：静态分组轨迹 + 可展开的搜索/抓取行）、来源账本、
> Markdown 渲染和**会话回放**已在 `apps/web` 实现（2026-10-29/30）。侧栏把
> dsh 会话 id 存在 `localStorage`，重新打开时通过
> `GET /v1/agent/sessions/{id}/replay` 读取 dsh 持久化的 `session.v4.jsonl.zstd`，
> 用同一张轨迹卡回放历史。子代理卡片（deep_research 的 job 进度/嵌套轨迹）
> 仍是预留设计，见 [CONTEXT_TRANSFER.md](../CONTEXT_TRANSFER.md) §6「P3.4」和
> [AGENT.md](AGENT.md)「Session persistence and replay」。

- **工作轨迹卡片（一个组件、一个位置）**：位于助手气泡顶部、答案上方，从研究到结束
  始终是同一张卡片，不会在答案下面再出现第二块。
  - **研究阶段**：旋转 orb +「正在研究」+ 步数/耗时/已查阅来源；当前工具组自动展开，
    组内显示查询行；完成的组自动收起；同类合并为「搜索了 3 次网页」。
  - **答案开始输出后**：同一卡片原地转为静态（无 spinner），头部变为「工作轨迹 ·
    13 步 · 58s · 5 个来源」，合并组行默认收起，20+ 次调用不会摊成 20+ 张卡片。
  - **展开**：点开组列出每次调用；点开搜索/抓取行显示查询、状态、结果数、主要域名、
    命中链接（新标签页）和耗时，**已引用** 徽标表示答案引用了该行 URL。
  - **计划与来源**：卡片底部按需展开计划、来源账本（已引用 / 仅查阅）和 token 用量。
- **工具卡片**：搜网页（web_search）、打开网页（web_fetch）、查公司资料、
  查财报、发起深研；显示查询/结果数/域名/耗时/是否被引用，不显示原始 JSON/HTML。
- **Markdown**：助手消息渲染 GFM（标题、粗体、列表、引用、表格、分隔线、代码、链接）；
  流式期间节流解析，表格在气泡内横向滚动；原始 HTML 不执行，链接只放行 http(s)。
- **子代理卡片**（预留）：agentic web search 或 `deep_research`；显示任务、状态、
  进度、当前步骤、嵌套子轨迹、摘要和来源；最多一级嵌套。目前 `deep_research`
  先以「发起深度研究」工具卡片呈现。
- **来源账本**：去重后的 URL，分「已引用 / 仅查阅」，放在「计划与来源」里，
  与计划、token 用量一起按需展开。
- **会话回放与历史对话**：页面刷新/重开后恢复上次会话的问答与轨迹；头部时钟按钮
  打开历史对话浮层（搜索、标题、相对时间、轮数，当前会话高亮），点选即载入该会话；
  「新对话」取消并清空当前会话。只回放父会话；dsh 子代理的子会话
  （`delegationDepth=1`）不出现在历史里。
- **不显示原始思考链**（`thought.delta`）；原始事件只在 local debug 模式可见。
- 侧栏宽度和布局不变；trajectory 在消息内滚动，不撑破侧栏（390px 已验收）。

- 关系图颜色：投资红/橙、供应绿、竞争灰、合作蓝；同时用线型区分状态。

### 后端缺口（2026-10-29 更新）

已补齐：

- `GET /v1/graph?company=&depth=&types=&status=` — 2 层图谱、全局 `/graph`。
- `GET /v1/indices/:code` — 指数成分；NDX = 100 家 QQQ 成分股。

仍缺：

- 生产静态托管（同源 API 或 nginx）；当前只有 `vite dev` / `vite build`。

partners/supplies/other/buys_from/licenses/joint_venture，没有

在数据到位前，空状态和"让助手去查"必须做好。
