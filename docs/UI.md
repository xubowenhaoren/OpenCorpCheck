## 0. 一句话

> **像用企查查一样查公司：搜一家公司，一页看完基本资料、财务、投资关系图、
> 新闻和来源；看不懂就直接问。**

三类核心动作：

1. **搜公司**（名称 / ticker / 中文名 / 一句话描述）
2. **看公司页**（基本资料 → 财务 → 关系图谱 → 新闻 → 来源）
3. **问一问**（任何页面右下角，带着当前公司上下文）

审核队列、研究运行、检索 explain、调试面板不进公开 UI，只保留 CLI / 内部页面。

## 1. 目标用户

| 用户 | 想干什么 | 熟悉的界面 |
|---|---|---|
| 非技术股民 | "这家公司靠什么赚钱、值不值得看、和谁有关系" | 同花顺、东方财富、雪球、企查查 |
| 普通金融从业者（非量化） | "快速了解一家公司、核对一个数字、看投资关系" | Wind、企查查、天眼查、公司公告 |
| 记者 / 内容创作者 | "找原始来源、复制引用" | 搜索引擎、企查查 |
| 学生 / 求职者 | "这家公司是做什么的、在哪里" | 百度、企查查 |

**共同点：**

- 看得懂财务名词，但不想读原始财报；
- 习惯"搜索 → 公司页 → 切 tab 看不同维度"的结构；
- 会用聊天框提问，但不会配置过滤器、写布尔查询、看关系图 JSON；
- 对"信息是否可信、来源在哪"有要求，但不关心抽取方法。

**不是目标用户：** 量化研究员、需要批量导出/API 的开发者、需要自定义报表的分析师。
这些能力保留在 CLI / MCP。

## 2. 从企查查借什么，不借什么

### 借

1. **顶部搜索 + 简单导航**：首页大搜索框；内页顶栏常驻搜索。
2. **公司页 = 页头 + tab + 右侧栏**：
   - 页头放公司名、代码、地区、行业、成立时间、关键标签；
   - tab 分维度：基本资料 / 财务数据 / 关系图谱 / 新闻动态 / 公告文件 / 资料来源；
   - 右侧栏放关键数字、主要股东/投资方、对外投资、相关公司。
3. **关系图谱是一等公民**：独立的「关系图谱」tab，中心节点 + 辐射布局 + 点击下钻 +
   右侧详情面板；下方同时提供列表视图。
4. **表格密度**：财务、股东、对外投资用紧凑表格，不用花哨图表。
5. **搜索结果带关键事实**：名称、代码、地区、行业、指数标签，一行看完。
6. **状态标签**：已核实 / 待核实 / 已报告（来源 pill 区分 13F 持仓、HKEX 权益披露、GLEIF 母公司、F10 股东），颜色 + 文字，不只靠颜色。

### 不借

1. **司法风险、商标、专利、招投标**等企查查的登记/风险数据——不是我们的数据范围。
2. **付费墙、会员、导出套餐**。
3. **企查查的蓝色品牌视觉**——借信息架构，不抄品牌；继续用现有的暖灰 + 绿色。
4. **信息轰炸**：不把几十个字段一次铺满，首屏只给结论和关键数字。
5. **内部工具入口**：审核、运行、调试不在产品导航里。

## 3. 设计原则

1. **熟悉的公司页结构，陌生的技术细节。** 页面结构像企查查；BM25、RRF、
   inferred、confidence、coverage tier、matchType、score 一律不出现。
2. **三个动作：搜 → 看 → 问。** 新增功能先问会不会多出第四个动作。
3. **关系图谱必须有，但不能是唯一入口。** 图 + 列表双视图；图为先，列表兜底，
   手机和无数据时也能用。
4. **数字必须能点回来源。** 每个财务数字、关系证据、新闻都带「来源」，点开是
   原文引用 + 网页链接 + 抓取时间；不显示抽取方法和技术字段。
5. **先说结论，再给细节。** 首屏：一句话 + 4 个关键数字 + 主要关系；完整财务表、
   全部来源、全部关系折叠在 tab 或"展开"里。
6. **数据缺失就说"暂无数据"。** 不猜、不补 0、不把 fixture 当真实数据。
7. **中文优先，英文可切换。** 公司名保留原文。
8. **手机可用。** 关系图在手机上提供全屏 + 列表两种形态。
9. **只读。** 普通用户不能改数据；修正走内部审核。
10. **可信感来自来源，不来自术语。** 用"来自 2025 年财报"而不是"confidence 0.95"。

## 4. 页面地图

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 首页 | 大搜索框、热门公司、最近查看 |
| `/search?q=` | 搜索结果 | 公司列表 + 市场/指数/行业筛选 |
| `/c/:ref` | 公司页 | 默认「基本资料」tab |
| `/c/:ref/financials` | 财务数据 tab | 核心指标 + 财务表 |
| `/c/:ref/graph` | 关系图谱 tab | 图 + 列表 |
| `/c/:ref/news` | 新闻动态 tab | 时间线 |
| `/c/:ref/filings` | 公告文件 tab | 官方公告/文件列表，来源打开 PDF |
| `/c/:ref/sources` | 资料来源 tab | 去重来源列表 |
| 任意页右侧 | AI 助手 | 可收起的右侧助手栏；手机全屏 |

顶部导航（内页）：

```text
OCC 公司百科     [搜索公司名、代码、中文名…]          首页  查公司  关系图谱   中文 ▾  ☾  ⬇(任务)
```

- **首页**：回 `/`。
- **查公司**：聚焦搜索框 / 回 `/search`。
- **关系图谱**：进入 `/graph` 全局图谱（见 §7.6）。
- 不放下拉菜单、不做多级导航。

`ref` 接受中文名、ticker、slug、ULID；解析失败显示候选，不静默跳转。

## 7. 公司页 `/c/:ref`

### 7.1 页头

```text
┌──────────────────────────────────────────────────────────────────────────┐
│  Apple Inc. 苹果公司                                     [关注] [问一问]  │
│  AAPL · NASDAQ · 美国 · 消费电子                                         │
│  成立 1976 · 员工 16.4 万 · 市值 3.4 万亿美元 · 数据更新于 2026-10-29    │
│  标签：NDX · 道琼斯                                                      │
├──────────────────────────────────────────────────────────────────────────┤
│  基本资料    财务数据    关系图谱    新闻动态    公告文件    资料来源     │
└──────────────────────────────────────────────────────────────────────────┘
```

- 名称：`displayName` + `legalName`（不同才显示）。
- 第二行：ticker、交易所、国家、行业。
- 第三行：成立时间、员工数、市值、数据更新时间；缺失项不显示。
- 标签：指数成分、市场板块（可选）。
- 动作：关注（本地）、问一问（打开右侧助手栏）。
- 页头在所有 tab 固定。

- 期间切换：年度 / 季度 / 半年度 / TTM，只显示该公司存在的口径，默认年度。
  每种口径单独请求（`financial_period_kind`），避免 200 行上限截断完整报表。
- 列按 `periodEnd` 倒序（年度 5 期、季度 6 期、半年度 4 期）；列头显示
  `periodLabel` 与该期主要来源徽标：`SEC 10-K/10-Q/20-F/40-F`、
  `东方财富 F10`、`研究资料`。
- 行数超过 12 时按报表分 tab（利润表 / 资产负债表 / 现金流量表）；否则堆叠展示。
- 美股季度是真实单季；A/HK 三季报是累计口径，列头带「累计」徽标。
- 推导值（毛利率、自由现金流、缺失时的毛利润/总负债）带「推导」徽标，
  不能当作原始报表行；单元格来源与列头不同时（如混入 F10 中期数据）单独标注。
- 覆盖行：来源 + 最新期间 + 财年结束日；存在推导值时追加「含推导值」。
- 每个数字可点开来源浮层（§7.7）；没有来源的格子为「—」。
- 手机端：表格横向滚动；不做趋势图（后续再评估）。

**图的行为**

- 以当前公司为中心；默认只展开 **1 层**，避免一屏几十个节点。
- 关系按类型分组，围绕中心排布：
  - **投资/股权**（红/橙）：`invests_in`、`owns`、`parent_of`
  - **供应商/客户**（绿）：`supplies`、`buys_from`
  - **竞争对手**（灰虚线）：`competes_with`
  - **合作/合资/授权**（蓝）：`partners_with`、`joint_venture_with`、`licenses_*`
  - **其他**（灰）
- 边方向从主体指向客体：投资方 → 被投公司；供应商 → 采购方。
- 边样式：
  - `verified`：实线 + 深色；
  - `inferred`：虚线 + 琥珀色，标签写"待核实"；

### 后端缺口（2026-10-29 更新）

已补齐：

- `GET /v1/graph?company=&depth=&types=&status=` — 2 层图谱、全局 `/graph`。
- `GET /v1/indices/:code` — 指数成分；已加载 NDX 100 / SPX 500 / A500 500 /
  HSI 85 / CYB50 50 / STAR50 50（A500/SPX 为 placeholder 成分，含 850 个
  stub；STAR50 为本地快照，2026-11-03 试点）。
- `GET /v1/sectors` — 搜索行业过滤。
- `GET /v1/search/companies?sector=` — Qdrant + Postgres 双侧过滤（`industry` 为同义参数）。
- 开发期用 Vite proxy（5173 → 8787），不需要 CORS。

仍缺：

- 生产静态托管（同源 API 或 nginx）；当前只有 `vite dev` / `vite build`。
- `GET /v1/entities/resolve?q=`（低优先级；`/c/:ref` 已能解析 ticker/slug/ULID）。
- 公司短摘要字段：当前 `description` 已覆盖，暂不需要单独字段。

**数据缺口（不是 UI 问题）**：投资/股权关系已开始由结构化 F10 股东表补强
（`owns` / `invests_in`，status `reported`，仅当股东已在公司库内），但覆盖仍
有限。GLEIF / SEC 13F / HKEX DION 是下一步；在数据到位前，空状态和"让助手去查"
必须做好。

## 14. 非目标

- 不做司法风险、商标、专利、招投标等登记数据。
- 不做行情 K 线、交易信号、组合管理。
- 不做用户账号体系（v1 只读公开页；关注存本地）。
- 不做自定义报表、批量导出（先支持复制引用/JSON）。
- 不做审核、运行、调试入口。
- 不做关系图编辑（只读）。
- 不在 v1 做财务趋势图（先表格）。
